# Настройка Supabase для синхронизации курсов между устройствами

## Что это даёт

Курсы хранятся в облачной PostgreSQL и синхронизируются в реальном времени через WebSocket. Когда админ меняет курсы на одном устройстве — **все остальные клиенты получают обновление мгновенно** (без перезагрузки страницы).

## Пошаговая настройка (5-10 минут)

### 1. Создайте проект Supabase

1. Зарегистрируйтесь на https://supabase.com (бесплатно)
2. Создайте новый проект (выберите регион, задайте пароль БД)
3. Дождитесь инициализации (~2 минуты)

### 2. Создайте таблицу `rates`

В **SQL Editor** выполните:

```sql
-- Таблица с курсами (единственная строка с id=1)
create table rates (
  id bigint primary key default 1,
  usd_thb float8 not null,
  rub_thb float8 not null,
  saved_at timestamptz not null default now()
);

-- Вставьте начальную запись
insert into rates (id, usd_thb, rub_thb, saved_at)
values (1, 34.12, 0.3538, now());

-- Разрешите чтение всем (публичный доступ для калькулятора)
alter table rates enable row level security;

create policy "Allow public read"
  on rates for select
  using (true);

create policy "Allow public write"
  on rates for update
  using (true)
  with check (true);
```

### 3. Включите Realtime для таблицы `rates`

1. Перейдите в **Database** → **Replication**
2. Найдите таблицу `rates` и включите переключатель **Enable**
3. Сохраните изменения

### 4. Получите credentials

1. Перейдите в **Settings** → **API**
2. Скопируйте:
   - **Project URL** (например, `https://abcdefgh.supabase.co`)
   - **anon public key** (длинная строка, начинается с `eyJ...`)

### 5. Добавьте credentials в проект

**Вариант A: Через переменные окружения (рекомендуется)**

Создайте файл `.env` в корне проекта:

```env
VITE_SUPABASE_URL=https://abcdefgh.supabase.co
VITE_SUPABASE_ANON_KEY=eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...
```

**Вариант B: Прямо в коде (быстро, но менее безопасно)**

Откройте `src/lib/supabase.ts` и замените плейсхолдеры:

```typescript
const SUPABASE_URL = "https://abcdefgh.supabase.co";
const SUPABASE_ANON_KEY = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...";
```

### 6. Пересоберите проект

```bash
npm run build
```

Готово! Теперь курсы синхронизируются между всеми устройствами.

## Как это работает

1. **При загрузке страницы** приложение читает курсы из Supabase (таблица `rates`, строка с `id=1`).
2. **Подписка на Realtime** открывается через WebSocket — приложение слушает изменения в таблице `rates`.
3. **Когда админ сохраняет курсы** (через админ-панель) — они записываются в Supabase.
4. **Все подключённые клиенты** мгновенно получают обновление через WebSocket и перерисовывают интерфейс.
5. **LocalStorage используется как кэш** — если Supabase недоступен, приложение работает офлайн с последними известными курсами.

## Проверка работы

1. Откройте сайт на двух устройствах (или в двух вкладках браузера)
2. Войдите в админ-панель на одном устройстве (Ctrl+Shift+A, пароль `1122`)
3. Измените курсы и нажмите «Сохранить»
4. На втором устройстве курсы обновятся **мгновенно** (без перезагрузки)

## Fallback: если Supabase не настроен

Если credentials не добавлены или Supabase недоступен — приложение автоматически переключается на LocalStorage (как раньше). Курсы будут работать, но **только на одном устройстве** — синхронизации не будет.

В консоли браузера вы увидите предупреждение:
```
Supabase: подписка не создана — credentials не настроены
```

## Безопасность

- **anon-key** предназначен для публичного использования на клиенте — это нормально
- Row Level Security (RLS) ограничивает доступ только к таблице `rates`
- Для дополнительной защиты можно добавить проверку IP или rate limiting в Supabase Dashboard

## Стоимость

Supabase Free Tier:
- 500 МБ базы данных
- 1 ГБ хранилища
- 50 000 активных пользователей в месяц
- 2 миллиона Realtime-сообщений в месяц

Для калькулятора валют этого более чем достаточно — бесплатный тариф покрывает тысячи одновременных пользователей.
